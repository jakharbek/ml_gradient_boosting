# Примеры: от 6 точек до миллиона строк

30 самостоятельных примеров градиентного бустинга. Они упорядочены от самых простых (ручной
счёт на 6 точках) до сложных рабочих задач (миллион строк, временные ряды, ранжирование,
эксплуатация). Уроки курса объясняют *почему*, примеры показывают *как это делается целиком*
на данных разного размера.

## Как устроен каждый пример

Каждый файл — готовый рассказ, который печатает всё по ходу работы:

| Часть | Что внутри |
|---|---|
| **Докстринг** | название, **цель**, **чему научитесь**, **датасет** (откуда, размер, что в нём), **этапы**, связанные уроки, команда запуска |
| **Этапы** | `── Этап 1. Данные ──`, `── Этап 2. …` — каждый шаг отделён и подписан |
| **Раскрытие датасета** | источник, число объектов и признаков, память, типы, доля пропусков, распределение цели или баланс классов, первые строки |
| **Выводы `▸`** | что мы только что увидели. Каждое утверждение проверено запуском, ключевые — ещё и `assert` |
| **Ячейки `# %%`** | файл открывается как ноутбук в VS Code / PyCharm / Jupytext и выполняется по ячейкам |

Все случайности зафиксированы (`seed`), поэтому числа при повторном запуске совпадают.
Синтетические наборы (`_data.py`) построены так, что **истинная зависимость известна**.
Примеры проверяют, нашла ли её модель.

## Jupyter-ноутбуки

У каждого примера есть ноутбук: `<уровень>/notebooks/NN_*.ipynb` (ссылки — в последнем столбце
таблиц ниже). Ноутбук уже **выполнен**: выводы, таблицы и графики сохранены, его можно читать
на GitHub или в VS Code, ничего не запуская. Внутри:

- вводная ячейка: уровень, цель, чему вы научитесь, данные, план этапов, время выполнения;
- ячейка «Подготовка» — работает из любой рабочей папки внутри репозитория;
- каждый этап — заголовок и код; выводы `▸` — оформленными блоками, первые строки данных — таблицей;
- в конце — «Попробуйте сами» (3 задания) и «Что дальше»: уроки курса и соседние примеры.

Ноутбуки **генерируются** из скриптов — источник истины один. Не правьте `.ipynb` вручную:

```bash
python examples/build_notebooks.py               # собрать и выполнить все 30 (≈ 7 минут)
python examples/build_notebooks.py --only 07 17  # только выбранные
python examples/build_notebooks.py --check       # все ли ноутбуки соответствуют скриптам
```

Уменьшенные данные в Jupyter: задайте `EXAMPLES_QUICK=1` в окружении до запуска Jupyter.

## Запуск

```bash
pip install -r requirements.txt                  # из корня репозитория
python examples/1_tiny/01_boosting_by_hand.py    # один пример; графики — в окнах
python examples/2_small/08_loss_functions_outliers.py --save --no-show   # сохранить рисунки в 2_small/figures/
python examples/4_large/22_million_rows_speed.py --quick                 # уменьшенные данные

python examples/run_all.py            # все 30 подряд со сводкой ✓/✗ и временем (≈ 6 минут)
python examples/run_all.py --quick    # быстрая проверка (≈ 4 минуты, в основном CatBoost и Optuna)
python examples/run_all.py --only 3_medium 22    # только уровень 3 и пример 22
```

Флаги одинаковы во всех примерах: `--save` сохраняет рисунки в `<уровень>/figures/`,
`--no-show` не открывает окна, `--quick` уменьшает данные (числа тогда отличаются от
таблицы ниже).

## Что проверено

- `python examples/run_all.py` — 30 из 30 примеров успешно; `--quick` — тоже.
- `python examples/build_notebooks.py` — 30 из 30 ноутбуков выполнены без ошибок и без предупреждений; `--check` — все актуальны.
- `ruff check examples` — без замечаний.
- Каждое утверждение в выводах `▸` сверено с фактическим выводом. Там, где результат не
  совпал с «ожидаемым по учебнику», примеры говорят об этом прямо. Так, на маленьких
  реальных наборах (06, 07, 09) линейные модели не хуже бустинга, а на изображениях (21)
  бустинг проигрывает SVM.
