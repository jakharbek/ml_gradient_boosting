Задача

Телеком-оператор хочет каждый месяц находить клиентов, которые, скорее всего, уйдут в следующем месяце, чтобы предложить им удержание. Ресурс ограничен: удерживать можно лишь небольшую долю базы. Поэтому важны и качество ранжирования, и честные вероятности (по ним считают ожидаемые потери).

Данные создаёт функция make_churn() из examples/churn_data.py: 4000 клиентов, 24 месяца, строка — «клиент в месяце». В данные заложено всё, что разбиралось в курсе.

План решения

1. Разбиение по времени

Модель будет предсказывать будущее, значит и проверять её нужно на будущем: обучение — месяцы 1–14, валидация — 15–18, тест — 19–24. Случайное разбиение смешало бы месяцы и дало бы оптимистичную оценку. Кроме того, после 18-го месяца цены выросли — тест проверяет модель в изменившихся условиях.

2. Метрики

Log-loss — честность вероятностей; ROC AUC — общее качество ранжирования; средняя точность (AP) — качество верха списка при редком классе (урок ). Точность (accuracy) бессмысленна: «никто не уйдёт» даёт 94%.

3. Базовые решения

Константа (доля уходов) — точка отсчёта для log-loss. LightGBM с параметрами по умолчанию — точка отсчёта для всего остального.

4. Улучшения по одному

Категории, ранняя остановка, поиск параметров, калибровка — каждое изменение проверяется на валидации. Тест смотрим для отчёта, но не выбираем по нему.

5. Объяснение и проверка

SHAP-важности: совпадают ли с пониманием бизнеса? Калибровка. Сдвиг между обучением и тестом: PSI, состязательная проверка.

Решение шаг за шагом

Эталонное решение — скрипт examples/capstone.py и ноутбук урока. Виджет показывает его результаты.

Бустинг по умолчанию — уже огромный шаг

Log-loss на тесте 0.229 → 0.179, AUC 0.50 → 0.84. Всё остальное — доводка.

Встроенные категории не помогли

На валидации log-loss 0.1508 против 0.1489 у числовых кодов. У region 60 значений с множеством редких, и встроенная обработка LightGBM с min_data_per_group = 100 работает с ними осторожно (урок ). Результат не угадывают — его проверяют.

Ранняя остановка и поиск дали главное улучшение

Тест: log-loss 0.1807 → 0.1721 → 0.1666, AP 0.379 → 0.393 → 0.419. Лучшие параметры — маленькие деревья (8 листьев) с большим минимумом объектов в листе (200) и сильным сглаживанием категорий: на шумной задаче с редким классом регуляризация важнее гибкости.

Калибровка почти ничего не изменила

Log-loss на тесте 0.1666 → 0.1665. Модель, отобранная по log-loss с ранней остановкой, уже была честной. Калибровка нужна не всегда — но проверять нужно всегда (урок ).

Сдвиг: где PSI молчит, а состязательная проверка — нет

PSI платежа между обучением и тестом всего 0.05: подорожание на 15% почти не меняет его широкое распределение. Состязательный классификатор отличает обучение от теста с AUC 0.89 — но в основном не из-за цен. Без платежа AUC 0.84, а по одному платежу — 0.56. Одни и те же клиенты встречаются в обеих частях, и по сочетанию «возраст + регион» классификатор узнаёт клиента, а по стажу — месяц. На панельных данных «клиент × время» состязательная проверка ловит не только сдвиг, но и время само по себе. Сравнивайте распределения внутри сопоставимых групп.

В коде

Полное решение — в ноутбуке урока. Старт для собственного решения (Jupyter):

import sys; sys.path.insert(0, "lessons/lesson_14/examples")
import lightgbm as lgb
from churn_data import FEATURES, make_churn, time_split

df = make_churn()
train, valid, test = time_split(df)
model = lgb.LGBMClassifier(n_estimators=3000, learning_rate=0.05, verbose=-1)
model.fit(train[FEATURES], train.churn, eval_X=(valid[FEATURES],), eval_y=(valid.churn,),
          callbacks=[lgb.early_stopping(100)])

Итоги курса

  1. Бустинг — сумма деревьев, каждое из которых идёт по антиградиенту потерь; второй порядок, штрафы и гистограммы делают его быстрым и устойчивым.
  2. Правильная валидация важнее выбора библиотеки; настройка — это в первую очередь размер деревьев, темп и ранняя остановка.
  3. Каждое утверждение о модели проверяется опытом — в этом курсе не раз оказывалось, что интуиция ошибается.
  4. Модель — это ещё и объяснение, честные вероятности, мониторинг и план переобучения.
