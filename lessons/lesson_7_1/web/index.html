Зачем это нужно

Число деревьев — самый важный гиперпараметр бустинга, и его почти никогда не задают вручную. Его находят ранней остановкой: обучение идёт, пока ошибка на валидации улучшается.

Это дёшево (одно обучение вместо перебора), надёжно и есть во всех библиотеках. Но у правила есть тонкости — шум валидации, выбор терпения, финальное обучение на всех данных.

Правило

  1. Отложите валидационную выборку.
  2. После каждого дерева считайте потери на валидации и запоминайте лучшее значение.
  3. Если лучшего значения не было patience итераций подряд — остановитесь.
  4. Верните модель к лучшей итерации: лишние деревья после неё отбросьте.

Кривая валидации шумная: она может ненадолго подрасти и снова пойти вниз. Слишком маленькое терпение останавливает обучение на случайном «бугорке», слишком большое — тратит время. Разумное значение — несколько процентов от ожидаемого числа деревьев, и чем меньше темп, тем больше терпение.

Тонкости

Валидация участвует в выборе — значит, она уже не тест

Лучшая итерация подобрана по валидации, поэтому ошибка на ней чуть оптимистична. Итоговое качество — на отдельном тесте.

Какую метрику отслеживать

Лучше всего — ту же функцию потерь, что оптимизируется (она гладкая). Точность или AUC ступенчаты и шумны на малой валидации (урок ).

Финальная модель на всех данных

Часто после выбора числа деревьев модель переобучают на обучении + валидации. Деревьев берут чуть больше найденного (например, ×1.1–1.2), так как данных стало больше. Надёжнее — выбрать число деревьев кросс-валидацией: среднее лучших итераций по фолдам.

Утечка через время

Для временных рядов валидация должна идти после обучения по времени — иначе ранняя остановка подстроится под будущее.

В коде

from gbcourse import datasets, GBRegressor
from xgboost import XGBRegressor

X, y = datasets.regression_1d(kind="wave", n=600, noise=0.6, seed=72)
X_tr, X_val, y_tr, y_val = datasets.train_test_split(X, y, test_size=0.3, seed=0)

m = GBRegressor(n_estimators=2000, learning_rate=0.05, max_depth=3, early_stopping_rounds=50)
m.fit(X_tr, y_tr, eval_set=(X_val, y_val))
print("gbcourse: обучено", len(m.history_["eval"]) - 1, "деревьев, оставлено", m.n_trees_)

xgb = XGBRegressor(n_estimators=2000, learning_rate=0.05, max_depth=3, early_stopping_rounds=50)
xgb.fit(X_tr, y_tr, eval_set=[(X_val, y_val)], verbose=False)
print("XGBoost: лучшая итерация", xgb.best_iteration)

Итоги

  1. Число деревьев выбирают по валидации: останавливаются, когда нет улучшения patience итераций, и возвращаются к лучшей.
  2. Терпение должно превышать «дрожание» кривой; с маленьким темпом его увеличивают.
  3. Итоговое качество оценивают на отдельном тесте; для финальной модели число деревьев надёжнее брать из кросс-валидации.
