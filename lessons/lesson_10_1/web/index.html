Зачем это нужно

Город, марка, категория товара, ID магазина — в табличных данных категорий больше, чем чисел. Способов подать их бустингу много, и выбор между ними заметно влияет на качество. В наших экспериментах разница между лучшим и худшим способом превышала 30%.

Способы по косточкам

Порядковые коды

Категории нумеруются 0, 1, 2, … и подаются как число. Дерево может делить только по порогу, то есть на «коды до t» и «после t». Если порядок кодов случаен, для выделения нужной группы нужны многие разбиения.

One-hot

По столбцу на значение. Каждое разбиение отделяет одну категорию от всех остальных — «одна против всех». При большом K это много редких столбцов и много мелких разбиений.

Кодирование средним (target encoding)

Категория заменяется сглаженным средним $y$: $\frac{\sum y + a\,p}{n + a}$. Наивный вариант (по всей обучающей выборке) даёт утечку, по фолдам — нет (урок ).

Встроенная обработка

LightGBM и XGBoost ищут разбиение вида «категория ∈ S» прямо в узле, CatBoost использует упорядоченные статистики. Как можно найти лучшее множество $S$ среди $2^{K-1} - 1$ вариантов — ниже.

Как найти лучшее множество категорий

В узле у каждой категории $k$ есть суммы $G_k$ и $H_k$. Разбиение категорий на группы $S$ и $\bar S$ оценивается обычным выигрышем $\frac{G_S^2}{H_S} + \frac{G_{\bar S}^2}{H_{\bar S}}$. Перебор всех групп — $2^{K-1} - 1$ вариантов: при $K = 30$ это полмиллиарда.

Теорема (Фишер, 1958; Брейман и др., 1984). Упорядочим категории по $G_k / H_k$ — среднему градиенту в категории. Тогда лучшая группа $S$ состоит из нескольких первых категорий этого порядка. Достаточно проверить $K - 1$ порогов, как у числового признака.

Именно так работает LightGBM: сортирует категории по $G_k / (H_k + \text{cat\_smooth})$ и проверяет пороги с обеих сторон. Это точное решение для одного узла, но и опасность. При многих редких категориях сортировка по шумным средним легко находит «идеальное» разбиение обучающих данных. Поэтому LightGBM требует минимум min_data_per_group = 100 объектов в группе, сглаживает cat_smooth = 10, проверяет не больше max_cat_threshold = 32 порогов. При $K \le$ max_cat_to_onehot = 4 используются разбиения «одна против всех». В XGBoost (enable_categorical=True) похожий алгоритм: max_cat_to_onehot = 4, а max_cat_threshold = 64 ограничивает число категорий в одной группе. Все значения проверены в ноутбуке урока.

Что лучше на практике

Данные: $y$ = эффект категории + $\sin x$ + шум с σ = 1 (значит, RMSE не может быть меньше 1). Частоты категорий убывают: много редких. 6000 объектов, разбиение 60/20/20, три повтора, темп 0.05 с ранней остановкой. Кодирования средним и one-hot подаются в LightGBM.

При 10 значениях всё равно

Все способы дают 0.97–0.98. При малом K любой способ позволяет деревьям выделить нужные группы.

При 100 значениях — встроенная LightGBM и кодирование средним

LightGBM встроенная 1.016, кодирование средним 1.026–1.030, XGBoost 1.034, CatBoost 1.047. Порядковые коды хуже (1.066), one-hot — худший (1.166).

При 1000 значениях — ни один способ не лучший всегда

Категория информативна: лучшие — встроенная XGBoost (1.295) и кодирование средним (1.297–1.312). Встроенная LightGBM (1.707) почти так же плоха, как порядковые коды (1.689): ограничение min_data_per_group = 100 не даёт выделять редкие категории. Категория — шум: встроенная XGBoost переобучается сильнее всех (1.123 при 1.020 без категории), наивное среднее — из-за утечки (1.087). Кодирование по фолдам (1.021), CatBoost (1.013) и LightGBM (1.020) безопасны.

Практический вывод. Кодирование средним по фолдам в этом эксперименте ни разу не было далеко от лучшего и не пострадало от шумовой категории — это надёжный выбор по умолчанию при большом K. Встроенную обработку стоит сравнить с ним на валидации: она может быть лучше (LightGBM при K = 100) или заметно хуже (LightGBM при K = 1000).

В коде

import numpy as np
import pandas as pd
import lightgbm as lgb
from gbcourse import datasets

x, c, y = datasets.categorical_regression(n=6000, n_categories=100, noise=1.0, seed=140)
perm = np.random.default_rng(0).permutation(len(y))
tr, va, te = perm[:3600], perm[3600:4800], perm[4800:]

def mean_table(c, y, K=100, a=10.0, prior=None):
    prior = y.mean() if prior is None else prior
    return (np.bincount(c, y, K) + a * prior) / (np.bincount(c, minlength=K) + a)

prior = y[tr].mean()
enc = mean_table(c[tr], y[tr], prior=prior)[c]                      # валидация и тест
fold = np.random.default_rng(0).permutation(len(tr)) % 5
for f in range(5):                                                     # обучение — по фолдам
    rows = tr[fold == f]
    enc[rows] = mean_table(c[tr][fold != f], y[tr][fold != f], prior=prior)[c[rows]]

variants = {"встроенная": pd.DataFrame({"x": x, "c": pd.Categorical(c)}),
            "среднее по фолдам": pd.DataFrame({"x": x, "enc": enc})}
for name, D in variants.items():
    m = lgb.LGBMRegressor(n_estimators=5000, learning_rate=0.05, verbose=-1)
    m.fit(D.iloc[tr], y[tr], eval_set=[(D.iloc[va], y[va])], callbacks=[lgb.early_stopping(100, verbose=False)])
    print(f"{name:18s} RMSE на тесте {np.sqrt(np.mean((y[te] - m.predict(D.iloc[te])) ** 2)):.3f}")

Итоги

  1. Лучшее разбиение категорий на две группы находится сортировкой по $G_k/H_k$ — это делают LightGBM и XGBoost.
  2. При малом K способ почти не важен; при большом — важен, и ни один не выигрывает всегда.
  3. Кодирование средним по фолдам — надёжный выбор по умолчанию; встроенную обработку сравнивайте на валидации.
  4. Наивное кодирование средним и встроенная обработка XGBoost переобучаются на шумовых категориях с множеством значений.
