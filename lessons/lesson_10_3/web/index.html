Зачем это нужно

Магазин прогнозирует спрос. Недопрогноз — пустая полка и потерянные продажи, перепрогноз — лишний товар на складе. Если недопрогноз вдвое-втрое дороже, минимизировать симметричную MSE — значит решать не ту задачу. Бустинг второго порядка позволяет обучаться на любой дважды дифференцируемой потере: достаточно дать ему $g$ и $h$ (урок ).

Асимметричная квадратичная потеря

Пусть $r = y - F$ — остаток; $r > 0$ означает недопрогноз. Штрафуем его в α раз сильнее:

$$L(y, F) = \begin{cases} \frac{\alpha}{2} r^2, & r > 0 \\ \frac12 r^2, & r \le 0 \end{cases} \qquad g = \frac{\partial L}{\partial F} = \begin{cases} -\alpha r \\ -r \end{cases} \qquad h = \begin{cases} \alpha \\ 1 \end{cases}$$

Лучшая константа для такой потери — не среднее и не квантиль, а экспектиль уровня $\tau = \frac{\alpha}{1+\alpha}$. При α = 1 это обычное среднее. У потери $h > 0$ везде, так что формулы второго порядка работают без оговорок.

Как передать библиотеке

XGBoost

Нативный интерфейс: xgb.train(params, dtrain, obj=f), где f(preds, dtrain) возвращает массивы grad и hess; preds — сырые прогнозы $F$. В sklearn-обёртке — objective=f(y_true, y_pred). Проверка в ноутбуке: своя псевдо-Хьюбер-цель дала прогнозы, совпадающие со встроенной reg:pseudohubererror до нуля.

LightGBM

LGBMRegressor(objective=f), f(y_true, y_pred) → (grad, hess). Своя метрика — eval_metric=m, m(y_true, y_pred) → (имя, значение, больше_лучше); по ней работает ранняя остановка.

Проверяйте g и h численно

Ошибка в знаке градиента — самая частая: модель «учится» в обратную сторону. Сравните свои $g$, $h$ с конечными разностями, как в уроке .

Четыре грабли

1. Старт LightGBM со своей целью — с нуля

Со встроенной целью LightGBM начинает с лучшей константы (среднего), а со своей — с $F_0 = 0$. На задаче Фридмана ($\bar y \approx 14$) своя L2-цель после 10 деревьев дала MSE 30.9 против 6.6 у встроенной; к 100 деревьям разница исчезла. Лечение — init_score в fit.

2. init_score не входит в predict

С init_score = ȳ деревья совпали со встроенной целью точно, но predict() возвращает только сумму деревьев. Стартовое значение нужно прибавить самому.

3. base_score в XGBoost — сырое значение

Со своей целью base_score — это стартовый $F_0$, а у встроенной binary:logistic — вероятность (урок ). Для своей цели ставьте разумный $F_0$ явно, например лучшую константу вашей потери.

4. Встроенная метрика LightGBM никуда не девается

Со своей целью LightGBM всё равно считает L2 на валидации, и ранняя остановка по умолчанию смотрит на первую метрику — на неё, а не на вашу. Передавайте metric="None". В упражнении 2 так остановка по доле недопрогнозов дала 75 деревьев, по асимметричной цене — 87. Без metric="None" обе остановились на одном и том же 41-м дереве. В XGBoost встроенную метрику отключает disable_default_eval_metric. Ещё одна мелочь: LightGBM смотрит на число аргументов вашей функции и третьим передаёт веса объектов, поэтому параметры потери передавайте через замыкание, а не через аргумент по умолчанию.

В коде

import numpy as np
import lightgbm as lgb
from gbcourse import datasets

ALPHA = 5.0
def asym_obj(y_true, y_pred):
    r = y_true - y_pred
    return np.where(r > 0, -ALPHA * r, -r), np.where(r > 0, ALPHA, 1.0)

def asym_cost(y_true, y_pred):
    r = y_true - y_pred
    return "асим. цена", float(np.mean(np.where(r > 0, ALPHA, 1.0) * r * r / 2)), False

X, y = datasets.regression_1d(kind="hetero", n=2000, noise=0.5, seed=161)
X_tr, X_te, y_tr, y_te = datasets.train_test_split(X, y, test_size=0.3, seed=0)  # данные упорядочены по x
F0 = np.full(len(y_tr), y_tr.mean())
for name, obj in (("L2", "regression"), ("асимметричная", asym_obj)):
    m = lgb.LGBMRegressor(n_estimators=200, learning_rate=0.05, num_leaves=8, objective=obj, verbose=-1)
    m.fit(X_tr, y_tr, init_score=F0 if callable(obj) else None)
    pred = m.predict(X_te) + (y_tr.mean() if callable(obj) else 0.0)  # init_score не входит в predict!
    print(f"{name:14s} асимметричная цена {asym_cost(y_te, pred)[1]:.3f}, доля недопрогнозов {np.mean(y_te > pred):.2f}")

Итоги

  1. Своя цель = две функции $g$ и $h$; при $h > 0$ бустинг второго порядка работает как со встроенной.
  2. Своя метрика нужна, чтобы ранняя остановка следила за тем, что важно для задачи.
  3. Задавайте стартовое значение явно: LightGBM со своей целью начинает с нуля, а init_score не входит в predict.
