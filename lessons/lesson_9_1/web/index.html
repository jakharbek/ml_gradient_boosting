Зачем это нужно

Устройство XGBoost мы разобрали в модуле . Теперь — ремесло: как его запускать, останавливать, проверять и объяснять. У каждого шага есть подвохи, из-за которых модель тихо получается хуже, чем могла бы.

Два интерфейса

sklearn-обёртка: XGBRegressor / XGBClassifier

Параметры задаются в конструкторе, обучение — fit(X, y, eval_set=[(X_val, y_val)]). Модель совместима с Pipeline, GridSearchCV, cross_val_score. Число деревьев — n_estimators (по умолчанию 100).

Нативный: xgb.train и DMatrix

Данные упаковываются в xgb.DMatrix(X, label=y) — внутренний формат с готовыми гистограммами и поддержкой пропусков. Параметры передаются словарём, число деревьев — num_boost_round (по умолчанию 10, а не 100!). Даёт доступ ко всему: своим целевым функциям (урок ), продолжению обучения, внешней памяти.

Одно и то же, разные имена

learning_rate ↔ eta, reg_lambda ↔ lambda, reg_alpha ↔ alpha, n_estimators ↔ num_boost_round. На одних данных и параметрах оба интерфейса дают одинаковые деревья (проверено в ноутбуке урока).

Ранняя остановка

В XGBoost 2 и новее early_stopping_rounds и eval_metric задаются в конструкторе. Если за указанное число деревьев метрика на последнем наборе из eval_set не улучшилась, обучение останавливается.

  • best_iteration считается с нуля: best_iteration = 99 означает 100 деревьев.
  • XGBoost не удаляет лишние деревья: в модели их best_iteration + 1 + early_stopping_rounds. Но predict sklearn-обёртки сам использует только лучшие. В нативном интерфейсе нужно передать iteration_range=(0, best_iteration + 1).
  • gbcourse поступает иначе — обрезает модель до лучшей итерации, а best_iteration_ там — число деревьев.

Набор, по которому останавливаемся, участвовал в выборе модели. Для честной итоговой оценки нужен третий, отложенный набор (урок ).

Лаборатория

Параметры названы как в XGBoost. Под капотом — наш движок в режиме newton с точным перебором, то есть алгоритм XGBoost tree_method="exact". Кнопка «Python» выдаёт код, который воспроизводит эксперимент в настоящем XGBoost.

Цифры будут близки, но не обязаны совпасть. В маленьких узлах глубоких деревьев часто бывают разбиения с равным выигрышем: например, узел из двух объектов делится по любому признаку одинаково. Библиотеки разрешают такую ничью по-разному, и на обучающих данных это незаметно, а на новых — заметно. В ноутбуке урока без γ прогнозы на обучении совпадают до $10^{-5}$ (глубина 3), а на валидации расходятся до 0.19. С γ > 0 добавляется разница в отсечении ветвей (урок ).

Пять видов важности

booster.get_score(importance_type=...) считает важность признака по всем узлам, где он использован для разбиения:

ТипЧто считаетКогда полезен
weightсколько раз признак использован для разбиенияпочти никогда: непрерывные шумовые признаки дают много мелких разбиений
gainсредний выигрыш разбиений по признакупо умолчанию в feature_importances_ (нормирован на сумму 1)
total_gainсуммарный выигрышвклад признака в уменьшение потерь целиком
coverсредняя сумма гессианов $H$ в узлахсколько «объектов» проходит через разбиения по признаку
total_coverсуммарная $H$редко

В задаче Фридмана признаки $x_5, \dots, x_9$ — чистый шум. XGBoost с ранней остановкой (75 деревьев, ν = 0.3) использовал их 207–268 раз, а информативный $x_3$ — самый сильный признак задачи — всего 292 раза. По частоте шум почти неотличим от сигнала. По total_gain разница в десятки раз: 176–270 против 2498–13201 у информативных. Но и gain-важности — лишь эвристика обучающей выборки. Более надёжные способы (перестановочная важность, SHAP) — в модуле .

Ещё три вещи, которые нужны каждый день

Категориальные признаки

Столбец pandas с типом category и enable_categorical=True: XGBoost ищет разбиения вида «категория ∈ множество» (при tree_method="hist"). Подробно о категориях — урок .

Пропуски

По умолчанию пропуск — это np.nan (параметр missing). Направление по умолчанию выбирается в каждом узле (урок ).

Сохранение модели

model.save_model("model.json") или .ubj (двоичный JSON) — переносимый формат, не зависящий от версии Python. pickle сохраняет весь объект Python и может не загрузиться в другой версии XGBoost.

В коде

import numpy as np
import xgboost as xgb
from gbcourse import datasets

X, y = datasets.friedman1(n=1000, noise=1.0, seed=92)
X_tr, X_val, y_tr, y_val = X[:700], X[700:], y[:700], y[700:]

model = xgb.XGBRegressor(n_estimators=1000, learning_rate=0.3, early_stopping_rounds=20, eval_metric="rmse")
model.fit(X_tr, y_tr, eval_set=[(X_val, y_val)], verbose=False)
print("лучшая итерация (с нуля):", model.best_iteration, "| деревьев в модели:", model.get_booster().num_boosted_rounds())

booster = model.get_booster()
for kind in ("weight", "total_gain"):
    score = booster.get_score(importance_type=kind)
    print(f"{kind:10s}", {k: round(v) for k, v in score.items()})

Итоги

  1. sklearn-обёртка удобна для конвейеров; нативный xgb.train даёт полный контроль. У num_boost_round по умолчанию всего 10 деревьев.
  2. После ранней остановки XGBoost хранит лишние деревья; sklearn-predict их игнорирует, нативный — нет.
  3. Важность weight обманчива; gain и total_gain лучше, но это тоже эвристика.
  4. Сохраняйте модель в JSON/UBJ, а не через pickle.
