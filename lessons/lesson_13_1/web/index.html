Зачем это нужно

Поиск, рекомендации, лента новостей: пользователь видит первые несколько результатов, и важен только их порядок. Ошибиться с десятым документом почти не страшно, с первым — очень. Обычная регрессия этого не знает. LambdaMART — бустинг, который учится именно порядку. Долгие годы он был стандартом промышленного поиска.

Постановка и метрика

Данные разбиты на запросы. У каждого запроса — список документов с признаками $x$ и оценкой релевантности $\mathrm{rel} \in \{0, 1, 2, 3, 4\}$. Модель выдаёт число $s(x)$, документы сортируются по убыванию $s$.

$$\mathrm{DCG@k} = \sum_{i=1}^{k} \frac{2^{\mathrm{rel}_i} - 1}{\log_2(i + 1)}, \qquad \mathrm{NDCG@k} = \frac{\mathrm{DCG@k}}{\mathrm{DCG@k}_{\text{идеальный}}} \in [0, 1].$$

Числитель поощряет высокую релевантность (экспоненциально), знаменатель $\log_2(i+1)$ снижает вес позиций внизу списка. Нормировка на идеальный порядок делает метрику сравнимой между запросами.

Три подхода

Поточечный: регрессия на оценки

Предсказываем $\mathrm{rel}$ как число. Просто, но потери одинаковы для ошибки на первой и на сотой позиции, и сравнивать документы разных запросов модель учится зря.

Попарный: RankNet

Для пары документов одного запроса с $\mathrm{rel}_i > \mathrm{rel}_j$ модель должна дать $s_i > s_j$. Вероятность правильного порядка $\sigma(s_i - s_j)$, потеря — log-loss: $\log\big(1 + e^{-(s_i - s_j)}\big)$. Градиент по $s_i$: $-\rho_{ij}$, где $\rho_{ij} = \frac{1}{1 + e^{s_i - s_j}}$ — вероятность неправильного порядка.

LambdaRank: вес — изменение NDCG

Попарная потеря не знает про позиции. LambdaRank (Бёрджес и др., 2006) умножает градиент пары на $|\Delta\mathrm{NDCG}_{ij}|$ — насколько изменилась бы метрика, если поменять $i$ и $j$ местами: $\lambda_{ij} = -\rho_{ij}\,|\Delta\mathrm{NDCG}_{ij}|$. Суммарная «лямбда» документа — сила, с которой его надо тянуть вверх или вниз. Ошибки в верхней части списка получают большие лямбды.

LambdaMART = бустинг по лямбдам

MART (Multiple Additive Regression Trees) — это градиентный бустинг. Каждое дерево строится по парам $(g_i, h_i)$, где $g_i$ — сумма лямбд документа, $h_i$ — сумма $\rho_{ij}(1-\rho_{ij})|\Delta\mathrm{NDCG}_{ij}|$. Дальше всё как в модуле . Реализация — 40 строк (пример урока).

Сравнение

Синтетические запросы (150 для обучения, 150 для теста, 10–30 документов в каждом), скрытая полезность $u = x_0 + 2x_1x_2 - 0.5x_3^2 + \varepsilon$, оценки 0…4 — квантили $u$ внутри запроса. 100 деревьев (пример examples/lambdamart.py).

Вес $|\Delta\mathrm{NDCG}|$ заметно улучшил попарный подход (0.866 → 0.889). Но на этих данных простая регрессия на оценки почти не уступила LambdaMART. Так бывает, когда оценки хорошо отражают полезность, а запросы похожи друг на друга. Преимущество списочных методов растёт, когда важен верх списка, а запросы сильно различаются. Проверяйте на своих данных.

В коде

В LightGBM запросы задаются размерами групп (строки одного запроса идут подряд), в XGBoost — номером запроса у каждой строки. Код для Jupyter; полный вариант — в примере урока.

import numpy as np, lightgbm as lgb, xgboost as xgb

group = np.bincount(qid)                    # число документов в каждом запросе (строки упорядочены по qid)
ranker = lgb.LGBMRanker(n_estimators=100, learning_rate=0.1, num_leaves=16)
ranker.fit(X, rel, group=group)
scores = ranker.predict(X_test)             # сортируйте документы запроса по убыванию

xr = xgb.XGBRanker(n_estimators=100, learning_rate=0.1, max_depth=4, objective="rank:ndcg")
xr.fit(X, rel, qid=qid)

Итоги

  1. Ранжирование оценивают NDCG@k: важны верхние позиции и высокая релевантность.
  2. LambdaRank взвешивает попарные градиенты изменением NDCG; LambdaMART строит по ним деревья второго порядка.
  3. Сравнивайте с простой регрессией на оценки: она бывает неожиданно сильной.
