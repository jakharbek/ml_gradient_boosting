Зачем это нужно

Темп обучения и число деревьев — два самых важных гиперпараметра бустинга. Их взаимосвязь проста, но её непонимание — самая частая причина плохих моделей.

В уроке с ν = 1 модель за два шага идеально подогнала крайнюю квартиру — на шумных данных такая жадность оборачивается переобучением. Маленький ν лечит это ценой большего числа деревьев.

Shrinkage: принимать лишь долю исправления

$$F_m(x) = F_{m-1}(x) + \nu \cdot h_m(x), \qquad 0 < \nu \le 1$$

Дерево $h_m$ говорит: «в этой области нужно прибавить столько-то». Мы прибавляем лишь долю ν. Оставшуюся часть исправят следующие деревья — уже с учётом других областей и других разбиений.

Представьте, что вы настраиваете звук с помощью десятка ручек. Можно выкрутить первую ручку до упора — и потом компенсировать остальными. А можно поворачивать все ручки понемногу по очереди. Второй путь дольше, но итоговая настройка аккуратнее: ни одна ручка не «перетягивает» звук на себя.

Связь с градиентным спуском

ν — длина шага в функциональном градиентном спуске (урок ). Маленький шаг идёт по «гладкой» траектории, большой — прыгает.

Много деревьев делят работу

Каждая область получает поправки от многих деревьев с разными разбиениями. Итоговая функция усредняет их пороги — становится глаже, меньше зависит от случайностей одного дерева.

Регуляризация: меньше разброс

При фиксированной «сложности пути» (примерно ν·M) маленький ν даёт модель с меньшим разбросом — в духе того, что усреднение даёт бэггингу.

Цена: нужно больше деревьев и ранняя остановка

При ν = 0.01 может понадобиться несколько тысяч деревьев. Их число выбирают по валидации.

Кривые валидации для разных темпов

Одни и те же данные, деревья глубины 3, пять темпов. Горизонтальная ось — число деревьев (логарифмическая шкала).

Три наблюдения, которые повторяются почти на любых данных (в среднем по разбиениям — на одном небольшом разбиении шум может их скрыть):

  1. Чем меньше ν, тем правее минимум: нужное число деревьев растёт примерно как $1/\nu$.
  2. Чем меньше ν, тем ниже (или не выше) минимум ошибки — до некоторого предела, после которого выигрыш исчезает.
  3. С большим ν переобучение наступает быстро и резко; с маленьким — медленно и плавно, поэтому выбрать M проще.

Песочница: темп и шаги

Сравните ν = 1 и ν = 0.05 при одной и той же итерации m = 10. Затем найдите m, при котором модель с ν = 0.05 выглядит так же, как модель с ν = 1 после 10 шагов.

Практические правила

  • Начните с ν = 0.1 и подберите число деревьев ранней остановкой.
  • Для финальной модели уменьшите ν в 2–10 раз и увеличьте M во столько же раз — обычно это даёт небольшой, но стабильный прирост.
  • ν > 0.3 оправдан только для быстрых экспериментов.
  • Никогда не подбирайте M по тестовой выборке — только по валидации или кросс-валидации.

В коде

import numpy as np
from gbcourse import datasets, GBRegressor

X, y = datasets.regression_1d(kind="wave", n=300, noise=0.5, seed=7)
for nu in (1.0, 0.3, 0.1, 0.03):
    curves = []
    for seed in range(5):                      # среднее по 5 разбиениям: одно разбиение слишком шумное
        X_tr, X_val, y_tr, y_val = datasets.train_test_split(X, y, test_size=0.3, seed=seed)
        m = GBRegressor(n_estimators=round(60 / nu), learning_rate=nu, max_depth=3).fit(X_tr, y_tr, eval_set=(X_val, y_val))
        curves.append(m.history_["eval"])
    ev = np.mean(curves, axis=0)
    best = int(np.argmin(ev))
    print(f"ν = {nu:4}: лучшая итерация {best:4d}, ν·M* = {nu * best:4.1f}, лучшая ½MSE {ev.min():.4f}")

Итоги

  1. Темп ν — доля исправления, которую принимает модель; он же длина шага функционального спуска.
  2. Меньше ν → лучше обобщение, но нужно ≈ пропорционально больше деревьев.
  3. Число деревьев выбирают по валидации; с маленьким ν кривая плавная и выбор надёжнее.
